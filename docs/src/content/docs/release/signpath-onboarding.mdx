Free code signing provided by [SignPath.io](https://signpath.io), certificate by [SignPath Foundation](https://signpath.org).

See also [Code Signing Policy](/release/code-signing-policy/) and [Signing and Release Runbook](/release/signing-and-release/).

## Onboarding Checklist

<Steps>
1. **Host on Public GitHub with GitHub-Hosted Runners:**
   SignPath Foundation verifies build provenance directly from public GitHub audit logs and requires builds on GitHub-hosted runners (`ubuntu-latest` and `windows-latest`):
   - Public repository: `https://github.com/zerovdd/zerovdd`
   - Dual `MIT OR Apache-2.0` license and free binary distribution
   - Protected `main` branch and `v*.*.*` tag rulesets, plus MFA enabled on all maintainer accounts
   - All third-party GitHub Actions pinned to 40-character commit SHAs

2. **Submit the SignPath Foundation Application:**
   Apply at [signpath.org](https://signpath.org), linking `https://github.com/zerovdd/zerovdd` and the [Code Signing Policy](/release/code-signing-policy/). Once approved, install the official **SignPath GitHub App** on `zerovdd/zerovdd`.

3. **Create the `zerovdd` Project & Three Artifact Configurations:**
   Because `zerovdd.cat` hashes the signed `zerovdd.dll` and the WiX MSI bundles signed EXEs, DLL, and catalog, `.github/workflows/release.yml` submits three sequential signing stages per architecture (`x64` and `ARM64`):

   | Order | Artifact Configuration Slug | Contents |
   | :--- | :--- | :--- |
   | 1 | `zerovdd-binaries` | `zerovdd.exe`, `zerovdd-svc.exe`, `zerovdd-tray.exe`, `zerovdd.dll` |
   | 2 | `zerovdd-catalog` | `zerovdd.cat` (generated by `Inf2Cat.exe` immediately after Stage 1) |
   | 3 | `zerovdd-msi` | `zerovdd-<version>-<arch>.msi` built by WiX v5 |

   Configure signing policy `release-signing` restricted to `.github/workflows/release.yml` on `refs/tags/v*` with manual MFA human approval (workflow timeout is `3600` seconds per stage).

4. **Set GitHub Actions Variables & Secret:**
   Under **Settings -> Secrets and variables -> Actions**:

   | Type | Name | Value |
   | :--- | :--- | :--- |
   | Variable | `SIGNPATH_ENABLED` | `true` |
   | Variable | `SIGNPATH_ORGANIZATION_ID` | SignPath Organization UUID |
   | Variable | `SIGNPATH_PROJECT_SLUG` | `zerovdd` (default) |
   | Variable | `SIGNPATH_SIGNING_POLICY_SLUG` | `release-signing` (default) |
   | Secret | `SIGNPATH_API_TOKEN` | Non-admin SignPath CI submitter token |

   Optional overrides if artifact slugs differ: `SIGNPATH_BINARIES_ARTIFACT_SLUG`, `SIGNPATH_CATALOG_ARTIFACT_SLUG`, `SIGNPATH_MSI_ARTIFACT_SLUG`.

5. **Tag, Approve & Verify on a Clean Host:**

   ```bash
   bash scripts/check-versions.sh --tag v0.1.0
   mise run release:preflight
   git tag -a v0.1.0 -m "Release v0.1.0"
   git push github main v0.1.0
   ```

   Approve the 6 SignPath requests (`binaries`, `catalog`, `msi` for `x64` and `ARM64`). Before publishing the draft GitHub Release, download the signed MSI on a clean Windows 11 host (`Secure Boot ON`, `HVCI ON`, `testsigning OFF`) and verify every signature:

   ```powershell
   Get-AuthenticodeSignature "C:\Program Files\ZeroVDD\zerovdd.exe"
   Get-AuthenticodeSignature "C:\Program Files\ZeroVDD\zerovdd-svc.exe"
   Get-AuthenticodeSignature "C:\Program Files\ZeroVDD\zerovdd-tray.exe"
   Get-AuthenticodeSignature "C:\Program Files\ZeroVDD\driver\zerovdd.dll"
   Get-AuthenticodeSignature "C:\Program Files\ZeroVDD\driver\zerovdd.cat"
   Get-AuthenticodeSignature ".\zerovdd-0.1.0-x64.msi"
   ```

   Confirm all six return `Status : Valid` with RFC 3161 timestamps, and verify `zerovdd doctor` reports `ROOT\ZEROVDD\0000` healthy (`problem=0`) with zero Code `31` or `CI.dll` Event `3004` errors.
</Steps>
